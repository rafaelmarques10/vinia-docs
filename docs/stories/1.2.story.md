## Dev Notes

### Ordem das migrations (respeitar dependências de FK)

```
1. restaurants          (sem FK)
2. users                (FK → restaurants, nullable)
3. wines                (FK → restaurants)
4. grapes               (sem FK)
5. grape_wine           (FK → wines + grapes)
6. tablets              (FK → restaurants)
7. sessions             (FK → tablets + restaurants + users nullable)
8. ai_interactions      (FK → sessions.id via uuid)
```

### Ponto de atenção — sessions.id é UUID

```php
// M006: sessions usa UUID como PK
$table->uuid('id')->primary();
// Isso exige sintaxe especial na FK em ai_interactions:
$table->uuid('session_id');
$table->foreign('session_id')->references('id')->on('sessions')->cascadeOnDelete();
// NÃO usar foreignId() — não funciona com UUID
```

### Ponto de atenção — users.restaurant_id nullable

```php
// M002: admin Vinia não pertence a nenhum restaurante
$table->foreignId('restaurant_id')->nullable()->constrained()->cascadeOnDelete();
```

### Ponto de atenção — wines.alcohol e price

```php
$table->decimal('alcohol', 4, 1)->nullable(); // ex: 13.5
$table->decimal('price', 10, 2);              // ex: 1250.00
```

### Nomes das migrations (padrão Laravel)

```
YYYY_MM_DD_HHMMSS_create_restaurants_table.php
YYYY_MM_DD_HHMMSS_create_users_table.php
YYYY_MM_DD_HHMMSS_create_wines_table.php
YYYY_MM_DD_HHMMSS_create_grapes_table.php
YYYY_MM_DD_HHMMSS_create_tablets_table.php
YYYY_MM_DD_HHMMSS_create_sessions_table.php
YYYY_MM_DD_HHMMSS_create_ai_interactions_table.php
```
> Usar timestamps crescentes para garantir ordem de execução.
